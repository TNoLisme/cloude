# 2. API Docs — Transfer Module HTTP Contract

> **Normative source:** `contracts/openapi.yaml`
> Tài liệu này diễn giải và bổ sung chi tiết implementation cho các endpoint thuộc module transfer.
> Nếu có sự khác biệt giữa tài liệu này và `openapi.yaml`, openapi.yaml là tài liệu có thẩm quyền.

## 1. Base URL & Headers chung

```text
Base URL: /api/v1
```

### Headers bắt buộc theo endpoint

| Header | Endpoint | Ý nghĩa |
|---|---|---|
| `Authorization: Bearer <accessToken>` | Tất cả | JWT access token, in-memory FE |
| `Content-Type: application/json` | POST có body | JSON payload |
| `Accept: application/json` | Tất cả | Expect JSON response |
| `Idempotency-Key: <uuid>` | `POST /transfers` | 16–128 printable ASCII; stable per intent |
| `X-Correlation-Id: <uuid>` | Optional tất cả | Per-user-action trace ID |

### Response headers transfer-specific

| Header | Khi nào xuất hiện | Ý nghĩa |
|---|---|---|
| `Idempotency-Replayed: true` | Khi replay | Response là result gốc |
| `X-Correlation-Id: <uuid>` | Tất cả response | Trace correlation |

## 2. Endpoint: Resolve Recipient

### `POST /api/v1/recipients/resolve`

**Access:** Customer (authenticated)
**Rate limit:** 30 request/phút/customer UUID

#### Request

```http
POST /api/v1/recipients/resolve
Authorization: Bearer <accessToken>
Content-Type: application/json

{
  "accountNumber": "100200300412"
}
```

`accountNumber`: 8–34 chữ số (theo OpenAPI); không thu hẹp còn 12 chỉ vì BE dùng 12.

#### Response `200 OK`

```json
{
  "accountId": "3285a3ab-4273-4ab2-987e-62bfc062a456",
  "accountNumberMasked": "••••3004",
  "recipientDisplayName": "Nguyễn Văn B",
  "currency": "VND"
}
```

#### Response `404 RECIPIENT_NOT_AVAILABLE`

```json
{
  "type": "about:blank",
  "title": "Recipient not available",
  "status": 404,
  "code": "RECIPIENT_NOT_AVAILABLE",
  "detail": "The recipient account could not be resolved.",
  "instance": "/api/v1/recipients/resolve",
  "correlationId": "..."
}
```

**Điều kiện trả 404:** Tài khoản không tồn tại, không phải ACTIVE, không phải VND, là tài khoản của chính customer đang thực hiện, hoặc tài khoản bị BLOCKED. Tất cả trường hợp đều trả cùng code `RECIPIENT_NOT_AVAILABLE` (concealment).

**Privacy rules:**
- Không trả phone, email, address, full account number.
- `recipientDisplayName` là limited display name (full name từ profile), không có thêm thông tin liên lạc.
- `accountId` (UUID) là dữ liệu cần thiết để tạo transfer; không phải data nhạy cảm.

**Implementation note:**
- Resolve qua `AccountModuleApi.findByAccountNumber(accountNumber)`.
- Kiểm tra: account tồn tại, `status = ACTIVE`, `currency = VND`.
- Không được resolve tài khoản của chính customer đang gọi (source ≠ destination validation ở create step).
- Không cache kết quả resolve — balance/status có thể thay đổi.

## 3. Endpoint: Create Transfer

### `POST /api/v1/transfers`

**Access:** Customer (authenticated, PIN configured)
**Idempotency-Key:** Required

#### Request

```http
POST /api/v1/transfers
Authorization: Bearer <accessToken>
Content-Type: application/json
Idempotency-Key: 3be4ec14-c219-4e50-a486-15dcc4d4a879
X-Correlation-Id: 47ec3533-9b7f-408c-a143-ab3918e56446

{
  "sourceAccountId": "a452a8cf-59f6-46f2-85a6-f2b8fd207db9",
  "destinationAccountId": "3285a3ab-4273-4ab2-987e-62bfc062a456",
  "amount": "50000",
  "currency": "VND",
  "pin": "123456",
  "memo": "Shared lunch"
}
```

**Amount rules:**
- String biểu diễn số nguyên VNĐ.
- Không được có phần thập phân, dấu `+/-`, space, leading zero, overflow.
- Range: `[2000, 10000000]`.
- Parse bằng `new BigDecimal(value)`, require `scale() == 0`, `signum() > 0`, `toPlainString().equals(input)`.

#### Case A: amount ≤ 5,000,000 VNĐ — Response `201 Created`

```json
{
  "transferId": "7a2327ae-b132-44a5-b682-982842717213",
  "status": "COMPLETED",
  "sourceAccountId": "a452a8cf-59f6-46f2-85a6-f2b8fd207db9",
  "destinationAccountId": "3285a3ab-4273-4ab2-987e-62bfc062a456",
  "amount": "50000",
  "currency": "VND",
  "memo": "Shared lunch",
  "createdAt": "2026-10-19T07:30:00Z",
  "completedAt": "2026-10-19T07:30:00Z"
}
```

Debit + credit committed atomically. Risk evaluation xảy ra AFTER_COMMIT.

#### Case B: amount > 5,000,000 VNĐ — Response `200 OK`

```json
{
  "transferId": "7a2327ae-b132-44a5-b682-982842717213",
  "status": "AWAITING_OTP",
  "expiresAt": "2026-10-19T07:32:00Z",
  "expiresInSeconds": 120,
  "message": "Transfer exceeds 5,000,000 VND. OTP sent to registered phone number."
}
```

**Không trừ/giữ tiền** khi trả `AWAITING_OTP`. Balance được kiểm tra lại tại confirm-otp.

#### Case C: Replay (cùng key + cùng hash)

```http
HTTP/1.1 200 OK
Idempotency-Replayed: true

{ <original response body> }
```

- Nếu transfer đang `AWAITING_OTP`: trả current state với remaining `expiresInSeconds` (không gửi OTP mới).
- Nếu transfer đã terminal (`COMPLETED`, `FAILED`, `EXPIRED`): trả current Transfer.

#### Error responses

| HTTP | Code | Điều kiện |
|---|---|---|
| `400` | `VALIDATION_ERROR` | Missing field, wrong type, invalid format |
| `400` | `AMOUNT_INVALID` | Amount ngoài range, fraction, overflow |
| `400` | `CURRENCY_MISMATCH` | currency ≠ VND, hoặc source/dest currency khác nhau |
| `400` | `PIN_INVALID` | PIN sai (attempts 1–4) |
| `403` | `PIN_LOCKED` | PIN bị lock (5 lần sai trong 15 phút) |
| `404` | `ACCOUNT_NOT_FOUND` | sourceAccountId không tồn tại hoặc không thuộc customer |
| `409` | `ACCOUNT_NOT_ELIGIBLE` | Source hoặc destination không phải ACTIVE |
| `409` | `INSUFFICIENT_FUNDS` | Balance không đủ |
| `409` | `IDEMPOTENCY_KEY_REUSED` | Cùng key nhưng khác payload |
| `429` | `RATE_LIMITED` | Quá rate limit |
| `503` | `SERVICE_UNAVAILABLE` | DB lỗi, hoặc OTP dispatch fail (large transfer) |

**Self-transfer:** `sourceAccountId == destinationAccountId` → `400 VALIDATION_ERROR`.

## 4. Endpoint: Confirm OTP (Step-up Transfer)

### `POST /api/v1/transfers/{transferId}/confirm-otp`

**Access:** Customer (source account owner only)

#### Request

```http
POST /api/v1/transfers/7a2327ae-b132-44a5-b682-982842717213/confirm-otp
Authorization: Bearer <accessToken>
Content-Type: application/json

{
  "otp": "849201"
}
```

#### Response `201 Created` — First confirm success

```json
{
  "transferId": "7a2327ae-b132-44a5-b682-982842717213",
  "status": "COMPLETED",
  "sourceAccountId": "a452a8cf-59f6-46f2-85a6-f2b8fd207db9",
  "destinationAccountId": "3285a3ab-4273-4ab2-987e-62bfc062a456",
  "amount": "6000000",
  "currency": "VND",
  "memo": "Large purchase",
  "createdAt": "2026-10-19T07:30:00Z",
  "completedAt": "2026-10-19T07:31:00Z"
}
```

#### Response `200 OK` — Replay after COMPLETED

```http
HTTP/1.1 200 OK
Idempotency-Replayed: true

{ <same Transfer body as above> }
```

Idempotent by `transferId`. Không cần Idempotency-Key header cho endpoint này.

#### Error responses

| HTTP | Code | Điều kiện |
|---|---|---|
| `400` | `OTP_INVALID` | OTP sai, attempts 1–4 (status vẫn AWAITING_OTP) |
| `404` | `TRANSFER_NOT_FOUND` | Transfer không tồn tại, hoặc actor không phải source owner |
| `409` | `STATE_CONFLICT` | Transfer đã FAILED (kể cả do sai OTP lần 5), hoặc confirm lần 5+ |
| `409` | `TRANSFER_EXPIRED` | Transfer đã EXPIRED (now > expires_at) |
| `409` | `INSUFFICIENT_FUNDS` | Balance không đủ khi re-validate dưới lock |
| `409` | `ACCOUNT_NOT_ELIGIBLE` | Account bị BLOCKED khi re-validate dưới lock |

**Lần 5 sai OTP:**
- OTP attempt được increment → 5 → challenge invalidated → transfer chuyển sang `FAILED` (failure_code: `OTP_ATTEMPTS_EXCEEDED`) — tất cả trong cùng transaction.
- HTTP response: `409 STATE_CONFLICT`.
- Các lần gọi sau trên transfer FAILED cũng trả `409 STATE_CONFLICT`.

**Concealment:** Destination owner gọi confirm-otp → `404 TRANSFER_NOT_FOUND` (không tiết lộ transfer tồn tại nhưng không thuộc quyền).

## 5. Endpoint: List Transfers

### `GET /api/v1/transfers`

**Access:** Customer (own transfers)

#### Query parameters

| Param | Type | Default | Mô tả |
|---|---|---|---|
| `limit` | integer | 20 | Range 1..100 |
| `cursor` | string | — | Opaque cursor (Base64 URL-safe) |
| `status` | string | — | `AWAITING_OTP`, `COMPLETED`, `EXPIRED`, `FAILED` |
| `from` | RFC3339 UTC | — | Inclusive |
| `to` | RFC3339 UTC | — | Exclusive |

`from < to` required khi cả hai đều có. `from >= to` → `400 INVALID_DATE_RANGE`.

#### Response `200 OK`

```json
{
  "items": [
    {
      "transferId": "7a2327ae-b132-44a5-b682-982842717213",
      "direction": "OUTGOING",
      "status": "COMPLETED",
      "counterpartyAccountMasked": "••••7710",
      "counterpartyDisplayName": "Nguyễn Văn B",
      "amount": "50000",
      "currency": "VND",
      "memo": "Shared lunch",
      "createdAt": "2026-10-19T07:30:00Z"
    }
  ],
  "nextCursor": "eyJ2IjoxLCJ0IjoiMjAyNi0xMC0xOVQwNzozMDowMFoiLCJpZCI6IjdhMjMyN2FlLWIxMzItNDRhNS1iNjgyLTk4Mjg0MjcxNzIxMyJ9"
}
```

**Visibility rules:**
- Source owner: thấy **mọi** status của transfer mình khởi tạo.
- Destination owner: chỉ thấy `COMPLETED` incoming transfer (tiền chưa đến nếu không COMPLETED).

**`direction`:** `OUTGOING` (source owner), `INCOMING` (destination owner).

**Cursor encoding:**
```text
CursorPosition {
  version: 1,
  timestamp: <created_at RFC3339 UTC>,
  id: <transfer UUID>
}
→ JSON UTF-8 → Base64 URL-safe (no padding)
```

**SQL next-page predicate:**
```sql
WHERE (created_at < :cursor_time)
   OR (created_at = :cursor_time AND id < :cursor_id)
ORDER BY created_at DESC, id DESC
LIMIT :limit_plus_one
```

Dùng `limit+1` để kiểm tra có trang sau không; encode cursor từ record cuối cùng được trả (không phải record thứ `limit+1`).

**Malformed cursor:** `400 VALIDATION_ERROR`.

| `failureCode` | Ý nghĩa |
|---|---|
| `OTP_ATTEMPTS_EXCEEDED` | 5 lần sai OTP |

## 7. Error Contract

Mọi error theo RFC 7807 Problem Details (`application/problem+json`):

```json
{
  "type": "about:blank",
  "title": "Business rule conflict",
  "status": 409,
  "detail": "Available balance is not sufficient for this transfer.",
  "instance": "/api/v1/transfers",
  "code": "INSUFFICIENT_FUNDS",
  "correlationId": "47ec3533-9b7f-408c-a143-ab3918e56446",
  "fieldErrors": []
}
```

`fieldErrors` (tùy chọn): `[{ "field": "amount", "code": "MINIMUM", "message": "..." }]`

FE branch theo `code`, không theo `detail` (có thể thay đổi). Stack trace không bao giờ được trả về client.

## 8. Module API Contracts (Ghép nối với module khác)

Các interface sau là input từ module khác — không sửa impl của họ:

```java
// Module: account
public interface AccountModuleApi {
    // Resolve account number → AccountView (masked number, display name, currency)
    AccountView findByAccountNumber(String fullAccountNumber);

    // Lock 2 accounts theo PostgreSQL UUID ASC order trong transaction hiện tại
    LockedAccountPair lockAccountsAscending(UUID accountA, UUID accountB);

    // Validate transfer eligibility (status, currency, ownership) dưới lock
    AccountTransferSnapshot validateTransferEligibility(UUID sourceId, UUID destinationId);

    // Atomic balance mutation — chỉ gọi dưới lock
    void debit(UUID accountId, BigDecimal amount);
    void credit(UUID accountId, BigDecimal amount);
}

// Module: identity
public interface IdentityModuleApi {
    // PIN verification — gọi trong REQUIRES_NEW transaction
    PinVerificationResult verifyPin(UUID customerId, String pin);

    // OTP issue cho TRANSFER_STEP_UP
    UUID issueOtp(UUID customerId, String purpose);

    // OTP consume — gọi trong money transaction (AWAITING_OTP confirm)
    OtpConsumeResult consumeOtp(UUID challengeId, String otp);
}

// Module: audit
public interface AuditModuleApi {
    // Append audit fact — gọi trong cùng money transaction
    void append(AuditFact fact);
}
```

## 9. Idempotency Rules chi tiết

| Scenario | Kết quả |
|---|---|
| Same key + same hash, transfer active | `200` với current state + `Idempotency-Replayed: true` |
| Same key + same hash, transfer terminal | `200` với terminal Transfer + `Idempotency-Replayed: true` |
| Same key + khác hash | `409 IDEMPOTENCY_KEY_REUSED` — không mutation |
| Concurrent same key + same hash | DB unique index → 1 insert wins, 1 gets replay |
| Concurrent same key + khác hash | DB unique index → 1 wins `409 IDEMPOTENCY_KEY_REUSED` |
| Confirm OTP sau COMPLETED | `200` replay, không trừ tiền lần 2 |

**PIN và idempotency:**
PIN được verify **mỗi lần gọi**, kể cả replay. PIN không thuộc payload hash.

**Key retention:** ≥ 24 giờ từ `created_at`. Không xóa key trong khi transfer còn có thể cần đối soát.

## 10. FE Integration Notes (ghép nối)

> Tham chiếu: `docs_draft/baseline/api-and-team-contract.md` §6.8–6.11, §8 (FE call sequences)

### Transfer flow sequence

```text
1. GET /accounts              → chọn source account
2. POST /recipients/resolve   → lấy accountId người nhận + masked info
3. Xác nhận form (source, dest, amount, memo)
4. Sinh Idempotency-Key (UUID) — 1 lần duy nhất khi user confirm
5. POST /transfers (+ Idempotency-Key, pin)
   if 201 COMPLETED → refresh accounts + history
   if 200 AWAITING_OTP → giữ transferId, hiện OTP modal + countdown
6. POST /transfers/{transferId}/confirm-otp
   if 201 COMPLETED → refresh accounts + history
   if 400 OTP_INVALID → cho nhập lại (server track attempts)
   if 409 STATE_CONFLICT/TRANSFER_EXPIRED → đóng modal, hiện trạng thái
7. timeout/network error → retry cùng key + payload (nhập lại PIN), hoặc GET /transfers/{id}
```

### Frontend không được làm

- Không sinh key mới sau timeout (vẫn dùng key cũ).
- Không suy ra outcome từ timeout — luôn đối soát.
- Không lưu PIN/OTP để retry tự động.
- Không optimistic debit UI trước khi có `201 COMPLETED`.
- Không tự cancel hoặc resend OTP (không có endpoint này).
