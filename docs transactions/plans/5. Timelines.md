# 5. Timelines — 3-Week Delivery Plan (2 Backend)

> **Start date:** Tuần 1 bắt đầu từ ngày 20/10/2026.
> **End date:** 08/11/2026 (3 tuần).
> **Nhân lực:** 2 backend developer trong scope module `transfer` — phân vai ở §1.
> **Bối cảnh:** Kế hoạch gốc 5 tuần/1 người được nén còn 3 tuần/2 người (~6 person-weeks). Việc nén này có rủi ro — xem §7.
> **Dependencies ngoài module (không đổi):** BE-A (PIN/OTP, block), BE-B (DisposablePostgresTestSupport, audit), FE (contract + error matrix).

## 1. Phân vai 2 backend

> Tên vai trò nội bộ của harness này (BE-Core / BE-Support). Việc gán thành viên thực tế do team quyết định; một người có thể kiêm nhiệm vai trò khác của team (ví dụ BE-A/BE-B) với điều kiện boundary `transfer/**` vẫn được tôn trọng.

| Vai trò | Trọng tâm | Sở hữu chính (trong `transfer/**`) |
|---|---|---|
| **BE-Core** (owner) | Nhất quán tài chính — money path | `CreateTransferService`, `ConfirmTransferOtpService`, lock/idempotency, state machine, failure injector, concurrency tests CON-*, FI-* |
| **BE-Support** | Vòng đời & truy vấn — read path | `ResolveRecipientService`, `TransferQueryService`, `TransferExpirationPolicy`, OTP dispatch adapter + compensation pairing, unit tests UT-*/QV-*/SM-*, evidence + FE error matrix |

**Nguyên tắc phân việc:**
- BE-Core giữ **mọi code chạm tới tiền** (debit/credit/lock/idempotency claim) — một đầu não duy nhất cho financial consistency.
- BE-Support không viết code trong money transaction; mọi thay đổi money path do BE-Core review.
- Cả hai đều chỉ commit trong `transfer/**` + `docs transactions/**` (theo AGENTS.md).
- Merge vào branch dùng chung qua PR, 1 PR = 1 scenario (quy tắc nghiêm cấm giữ nguyên).

## 6. Acceptance Criteria tổng hợp

Trước khi mark **Done**, tất cả checklist sau phải pass và có evidence (source: [Architecture](./3.%20Architecture.md) §10, [Advanced Business](./7.%20Advanced%20Business.md) §8):

### Financial Invariants

- [ ] Rollback: source/dest balance unchanged sau failed transaction (AF-01)
- [ ] Zero negative balance dưới concurrent overdraft attempt (AC-01)
- [ ] Timeout retry trả original result, 1 debit/credit duy nhất (AF-02)
- [ ] Opposite-direction không deadlock lâu dài (AC-03)

### State Machine

- [ ] ≤5M → COMPLETED ngay (1 DB transaction); 5M đúng ranh giới → small path
- [ ] >5M → AWAITING_OTP; không trừ/giữ tiền; expires_at = now+120s; 5M+1 → large path
- [ ] OTP đúng + re-validation ok → COMPLETED; debit/credit committed
- [ ] OTP sai 1–4 → 400 OTP_INVALID; status vẫn AWAITING_OTP; attempts committed
- [ ] OTP sai lần 5 → FAILED(OTP_ATTEMPTS_EXCEEDED); 409 STATE_CONFLICT
- [ ] Expired → 409 TRANSFER_EXPIRED; balance unchanged; lazy expiry hiển thị đúng
- [ ] Terminal không ghi đè: COMPLETED/EXPIRED/FAILED → final (test cố ghi đè phải fail)

### Idempotency

- [ ] Same key + same payload → 1 transfer; replay trả result gốc
- [ ] Same key + khác payload → 409 IDEMPOTENCY_KEY_REUSED; không mutation
- [ ] Concurrent same key → 1 resource (DB unique constraint)
- [ ] Duplicate confirm → 1 debit/credit; replay 200
- [ ] App restart giữa commit và retry → replay vẫn đúng

### Query & Visibility

- [ ] Source owner thấy mọi status; destination owner chỉ thấy COMPLETED
- [ ] Destination truy cập non-completed → 404 TRANSFER_NOT_FOUND
- [ ] Cursor stable, tie-break đúng, malformed → 400; filter status/date đúng inclusive/exclusive

### Security

- [ ] PIN invalid → 400; PIN locked → 403; không bước vào OTP
- [ ] Concurrent wrong PIN preserve lockout (AC-06)
- [ ] IDOR: customer không truy cập transfer của customer khác
- [ ] Wrong-attempt state committed trước HTTP error response

### Infrastructure

- [ ] Dùng `DisposablePostgresTestSupport` của BE-B (hoặc đã đổi trả từ fallback tạm thời)
- [ ] H2 không được dùng cho concurrency/lock tests
- [ ] `TransferFailureInjector` không lọt prod profile

## 9. Quy tắc nghiêm cấm

| Hành động | Lý do |
|---|---|
| Sửa `identity/**`, `account/**`, `audit/**`, `risk/**` | Vi phạm module boundary; proposal nếu cần |
