# BE-TRF-04/05 — Candidate implementation evidence

> 17/11/2026. Partial implementation inventory; not task completion, provider integration, end-to-end evidence or release approval. BE-TRF-04 seam orchestrator, UUID challenge boundary and T0 port added (DEC-TRF-017); candidate source and tests are uncommitted and may change. Reviewer: pending.

## Scope present in source

- `TransferCreateInput` is a candidate input parser wired into the BE-TRF-03 boundary candidate, not a registered production endpoint. Ten passing tests cover request shape, UTF-8, byte-size bounds, idempotency header, field validation and safe `errors[].field`. It does not enforce the no-PII policy for descriptions or keys; authentication, authorization, HTTP security, Problem mapping and runtime wiring remain outstanding.
- `TransferRequestHash`, `IdempotencyDecision`, `StepUpAmountPolicy`, `IdempotencyRetention` and `TransferReferenceGenerator` provide isolated canonical hash, idempotency classification, amount trigger, retention calculations and reference generation (proposed OQ-02 shape, SecureRandom; format not frozen). They do not provide authorization, locks, reservations, database lookup, HTTP replay or purge.
- `TransferPreflightCandidate` is an unregistered orchestration candidate. Its 13 fake tests cover primary lookup before preflight, reread on rejection, winner/conflict/replay handling, sequencing, binding, `ChallengeRequired` carrying the request hash, and `Settlement` receipt/outcome consistency. The candidate hashes an immutable payload and checks the T1 actor, customer, key, hash, source, resolved destination, amount/currency and description against it. Account-number resolution still depends on the trusted Account port; the caller must authenticate and authorize, and real provider, HTTP boundary and security/contract tests remain necessary before activation.
- `TransferIntentCandidate` is an unregistered T1 candidate using internal ports and a transaction template. Its 14 fake tests cover guard and key recheck, the UUID `challengeRef` snapshot boundary (insert NULL FK → consume UUID → attach BIGINT FK before flush/audit), typed challenge rejection (mismatch/expired) and audit-write failure rolling back all of T1, simulated unique-key rollback, reading the winning record after rollback, and fail-closed TTL snapshot validation. They do not establish real database transaction semantics or provider behavior.
- `TransferCreateOrchestrator` is an unregistered candidate implementing the `TransferOrchestrator` seam for the BE-TRF-03 boundary (DEC-TRF-017). Its 14 fake tests (real preflight candidate + fake ports + fake Identity port) cover outcome mapping (Completed/Failed/Replay/InProgress/Conflict/typed preflight denials), T0 `requestChallenge` bound to actor/hash/key after the gate, and error mapping: challenge mismatch→409, expired→410, audit write→500, OTP dispatch→503, system errors propagate, no outer transaction, server-side customer required. `StepUpChallengePort` (5 tests) is the consumer seam for TRFC-ID-02/05; its `ChallengeIssued` display fields are a proposal pending Identity review. No production bean is registered; the preflight adapter wiring (findVerifiedBindingIfPresent, Account ownership/status, TTL config read) and real providers remain outstanding.
- `TransferSettlementCandidate` is an unregistered T2 candidate using internal ports for guard/fence, account/usage locks, fraud, money/ledger, reservation, terminal/outbox and audit ordering. It compares both epoch and token with the locked fence. Its 19 fake tests include the recovery entry point's `MANDATORY` transaction and rollback-only propagation. Five additional PostgreSQL tests use test-only synthetic provider implementations and tables: success, injected failure rollback, insufficient-balance outcome, stale token/two concurrent attempts, and recovery rollback-only propagation when an inner failure is caught. They establish behavior only for that fixture, not durable production fencing, provider transactions or full recovery.
- Subsequent changes add an opt-in fraud savepoint and positive integer rule version; see [BE-TRF-05 savepoint evidence](BE-TRF-05-savepoint.md). The candidate propagates credit errors; it does not implement credit savepoint recovery, Tfail, retries or reconciliation. Recovery orchestration and ambiguous-commit resolution remain incomplete. No candidate is production-wired; real provider adapters, authorization, PII/security controls and a complete money path remain outstanding. Internal ports are candidate seams, not implemented or approved provider-owned APIs. See [BE-TRF-02 candidate evidence](BE-TRF-02-candidate-verification.md) for the separate migration/fixture scope; synthetic provider tables are not provider migrations.
